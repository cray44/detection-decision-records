# DDR v0.4 — Splunk Target Completeness Design

**Status:** Plan drafted. Awaiting IMPLEMENT signal.
**Decided:** 2026-05-06
**Theme:** Promote Splunk-native targets from "scaffold + hand-edit" to "first-class, fully automated."

---

## Decision

v0.3 design doc explicitly defers two things to v0.4: full `savedsearches.conf` parser and Splunk `query_hash` refresh. Bundle them — they go together (can't refresh a hash if you can't parse the conf).

Out of scope for v0.4: Elastic/KQL exporters (v0.5+), `ddr list` (v0.5+), multi-rule targeting (v0.5+), upstream RFC (v1.0).

---

## 7-Section Plan (locked)

### 1. Refined Goal & Success Criteria

A Splunk admin can:
- `ddr new --target splunk savedsearches.conf --name <stanza>` → fully populated DDR with `query_hash`, `path_or_url`, inferred `app`. No hand-editing of target block.
- `ddr refresh-hash <splunk_ddr>` → re-parses conf, recomputes hash, prints old/new (parallel to Sigma behavior).
- `ddr validate --strict` warns on `query_hash` drift when local conf is reachable.
- v0.1/v0.2/v0.3 records continue to validate unchanged.

### 2. Proposed Changes / Feature Breakdown

**Schema:** `ddr_version` Literal accepts `"0.4"`. No other schema changes — `query_hash` field already exists from v0.3.

**New module `ddr._internal.splunk_conf`:**
- `parse_savedsearches_conf(path) -> dict[stanza, dict[key, value]]` — handles `\`-continuation, `#` comments, BOM, CRLF, multi-stanza
- `extract_stanza(conf, name) -> dict` — single stanza or error
- `infer_app_from_path(path) -> str | None` — `.../etc/apps/<app>/local/savedsearches.conf` → `<app>`
- `canonicalize_spl(query) -> str` — strip BOM, LF-normalize, join continuations, drop line comments, collapse whitespace, trim. **No keyword lowercasing** (preserves field-value semantics).
- `compute_query_hash(query) -> str` — `sha256:<hex>` of canonicalized SPL

**CLI changes:**

| Command | Change |
|---|---|
| `ddr new --target splunk <conf_path> --name <stanza>` | Parses conf, extracts stanza, computes `query_hash`, fills `path_or_url`, infers `app` (overridable with `--app`). |
| `ddr new --target splunk <conf_path>` (no `--name`) | If exactly one stanza → use it. If >1 → exit 1 listing stanzas. |
| `ddr new --target splunk --name <stanza>` (no path) | Existing v0.3 behavior — minimal scaffold without `query_hash`. |
| `ddr refresh-hash <splunk_ddr>` | Branches on `target.kind`. Splunk path: re-parses `path_or_url` (or `--conf` override), recomputes. Same old/new output. |
| `ddr refresh-hash --conf <path>` | New optional flag — explicit conf override (parallels existing `--rule`). |
| `ddr validate --strict` | New check: if `target.kind=splunk` AND `query_hash` present AND `path_or_url` resolves locally → recompute, WARN on drift. |

**Examples:**
- Update `examples/06-splunk-native-savedsearch/ddr.yml` to include real `query_hash` (the implementation now produces it). README addendum: "regenerate with `ddr refresh-hash`."
- Optional new example 07: multi-stanza Splunk Add-on conf demonstrating stanza selection.

**Spec & schema files:**
- `spec/ddr-v0.4.md` — formalizes SPL canonicalization algorithm v1
- `spec/ddr-v0.4.schema.json` — regenerated
- `spec/CHANGELOG.md` — additive entry

### 4. Edge Cases & Error Handling

`savedsearches.conf` is gnarly. Splunk INI dialect quirks:

| Case | Handling |
|---|---|
| Multi-line `search =` with trailing `\` | Join, normalize whitespace |
| `#` mid-line | Treated as data (Splunk only honors `#` at line start) |
| Stanza names with spaces / special chars | Preserve verbatim |
| `[default]` stanza | Skip — never a DDR target |
| Stanza absent from file | Error: lists available stanzas |
| Multiple `search =` keys in one stanza | Last-wins (Splunk behavior) |
| `disabled = 1` stanza | Allow but WARN |
| Empty `search` value | Error |
| BOM-prefixed file | Strip before parse |
| CRLF | Normalize to LF |
| `--name` mismatch with file | Exit 1, list real stanzas |
| Multi-stanza file, no `--name` | Exit 1 unless single stanza |
| `query_hash` drift on validate | WARN, don't fail (parallel to Sigma) |
| `refresh-hash` on already-current hash | "Hash unchanged" (existing pattern) |
| `path_or_url` is HTTP URL, not local path | `refresh-hash`/`validate` skips drift check, prints note |

**Canonicalization algorithm (formalize in `spec/ddr-v0.4.md`):**
1. UTF-8 decode, strip BOM
2. CRLF → LF
3. Join `\`-continued physical lines
4. Drop line-leading `# ...` comments
5. Collapse runs of whitespace to single space
6. Trim outer whitespace
7. SHA-256 → hex → `sha256:` prefix

No keyword lowercasing — Splunk commands are case-insensitive but field values aren't, and DDR can't safely distinguish them.

### 5. Testing Strategy

**Unit (`tests/test_splunk_conf.py` — new):**
- Parser: simple stanza, multi-line `search`, comments, BOM, CRLF, multi-stanza, missing stanza, malformed `[`, `[default]` skip
- `infer_app_from_path`: app dir match, non-app paths return None
- `canonicalize_spl`: idempotent (`canon(canon(x)) == canon(x)`); whitespace-only diffs → same hash; semantic diffs → different hash
- `compute_query_hash`: format check (`sha256:<64 hex>`)

**Unit (`tests/test_cli.py`):**
- `ddr new --target splunk <conf> --name <stanza>` → scaffold has hash + path + inferred app
- Single-stanza conf without `--name` → uses it
- Multi-stanza conf without `--name` → exit 1, lists stanzas
- `--name` not in file → exit 1
- `--name` only (no path) → existing v0.3 minimal scaffold path still works
- `ddr refresh-hash` on splunk DDR → updates hash, prints old/new
- `ddr refresh-hash --conf <path>` → override works
- `ddr refresh-hash` on splunk DDR with unchanged SPL → "Hash unchanged"
- `ddr validate --strict` on stale-hash record → WARN

**Integration:**
- Example 06 round-trip (parse → new → refresh-hash idempotent)
- Realistic Splunk_TA_* multi-stanza conf

**Schema:**
- v0.1/v0.2/v0.3 fixtures all validate under v0.4
- Drift check on v0.4 passes after regen

### 6. Sigma Compatibility & Ecosystem Fit

Splunk-only release; doesn't touch Sigma path. But it **strengthens the upstream pitch** by proving DDR handles SIEM-native operational reality at parity with Sigma:

- `query_hash` algorithm intentionally mirrors Sigma's `content_hash` shape: canonicalize → SHA-256 → `sha256:` prefix. Different canonicalization rules, identical interface.
- Same `refresh-hash` UX across both target kinds. Same drift-warning semantics in `validate --strict`.
- Teachable: *"every target has a hash, every drift is a warning, every refresh is idempotent."* Consistency is the spec's marketing.

### 7. Final Plan Summary

v0.4 closes the gap left by v0.3's minimal Splunk scaffold. A new pure-Python `splunk_conf` module parses `savedsearches.conf` (handling `\`-continuation, comments, BOM, multi-stanza), infers app from path, and canonicalizes SPL into a hashable normal form formalized in `spec/ddr-v0.4.md`. `ddr new --target splunk <conf> --name <stanza>` produces a fully-populated record including `query_hash`. `ddr refresh-hash` branches on `target.kind`, parallel to the existing Sigma path. `ddr validate --strict` warns on `query_hash` drift. Schema bumps `ddr_version` to accept `"0.4"` and is otherwise unchanged — v0.1/v0.2/v0.3 records validate untouched. No new runtime dependencies, no breaking changes, ~20 new tests. Sets up v0.5 for `ddr list` + Elastic/KQL exporters.

## Architecture notes

**SPL canonicalization is intentionally minimal.** No keyword lowercasing, no AST parsing, no field-name normalization. The hash answers one question: *"has this savedsearch been edited since the DDR was authored?"* — not *"are these two SPLs semantically equivalent?"* Whitespace and comment changes are noise; everything else is signal.

**Stanza name as primary key.** A savedsearches.conf is keyed by stanza name; that's what `query_ref.name` already stores. The parser returns `dict[stanza_name, dict[key, value]]` and the CLI selects by exact name.

**App inference is best-effort.** If `path_or_url` matches `.../etc/apps/<app>/(local|default)/savedsearches.conf`, return `<app>`. Otherwise return None and require `--app`. Don't try to be clever — `search` is a fine default and the user can override.

**HTTP `path_or_url` skips drift check.** v0.4 doesn't fetch URLs. If `path_or_url` is `http(s)://...`, `refresh-hash` requires `--conf` and `validate --strict` prints a note that drift can't be verified.
