# DDR v0.3 — Splunk-Native Target Design

**Status:** Plan drafted. Awaiting IMPLEMENT signal.
**Decided:** 2026-05-06
**Theme:** Lift the Sigma-only target assumption. Add a `target.kind = "splunk"` variant for SIEM-native records.

---

## Decision

v0.3 adds a **Splunk-native target** alongside the existing Sigma target — additive schema change, full back-compat for v0.1/0.2 records. Picked because the v0.2 design explicitly defers it to "v0.3+" and it unblocks the multi-SIEM story the v1.0 north star requires.

Out of scope for v0.3: Elastic/KQL exporters (separate release), multi-rule targeting (separate release), `ddr list` command (separate release), full savedsearches.conf parser (v0.4 — v0.3 ships a minimal scaffold).

---

## 7-Section Plan (locked)

### 1. Refined Goal & Success Criteria

DDR v0.1/0.2 assume every record targets a Sigma rule. Real detection programs have detections that live only in the SIEM — savedsearches written in SPL, never expressed as Sigma. v0.3 lifts that assumption by adding a `splunk` target kind alongside the existing `sigma` kind.

**Success:** A detection engineer with a Splunk-native savedsearch can:
- `ddr new --target splunk` to scaffold a record (minimal — hand-edit boilerplate, no .conf parsing in v0.3)
- Author a `suppress` decision whose tuning is a raw SPL filter clause (no Sigma selections)
- `ddr validate` it
- `ddr export-splunk` it directly — sigma-to-spl is **not required** for native records
- Mix Sigma-targeted and Splunk-targeted records in the same directory; `ddr validate examples/` accepts both

Sigma-targeted v0.1/0.2 records continue to validate against the v0.3 schema unchanged. Schema bumps to `0.3` with **additive** changes only.

### 2. Proposed Changes / Feature Breakdown

**Schema (`src/ddr/models/record.py`):**

Existing `Tuning` is renamed `SigmaTuning` (alias retained for back-compat); existing `SigmaTarget` keeps its name.

New models:
```
SplunkQueryRef:
  name: str                # savedsearch stanza name
  app: str                 # Splunk app context (e.g. "search", "DA-ESS-AccessProtection")
  query_hash: str | None   # sha256 of normalized SPL (optional in v0.3 — v0.4 automates)
  path_or_url: str | None  # link to source / savedsearches.conf path

SplunkTarget:
  kind: Literal["splunk"]
  query_ref: SplunkQueryRef

SplunkTuning:
  kind: Literal["splunk"]
  filter_title: str | None
  filter_description: str | None
  splunk_filter: str       # raw SPL — author writes the FP clause directly
```

Discriminated unions:
- `Target = Annotated[SigmaTarget | SplunkTarget, Field(discriminator="kind")]`
- `Tuning = Annotated[SigmaTuning | SplunkTuning, Field(discriminator="kind")]`

Cross-field validator on `DDRRecord` (mode="after"): if decision is `suppress`, `target.kind` must equal `decision.tuning.kind`.

Version field: `ddr_version` accepts `"0.1"` | `"0.2"` | `"0.3"`.

**CLI:**

| Command | Change |
|---|---|
| `ddr new` | New `--target` flag (default: `sigma`). For `--target splunk`: accepts a savedsearches.conf path *or* `--name <stanza>`; emits a minimal scaffold with TODO placeholders. Full .conf parsing → v0.4. |
| `ddr validate` | No code change — Pydantic discriminated union handles it. |
| `ddr export-splunk` | Branches on `target.kind`. Sigma → existing v0.2 lowering path. Splunk → emit `splunk_filter` as-is, normalized (strip leading `NOT `, wrap in `NOT (...)` for fragment, format stanza for savedsearches). |
| `ddr export-sigma-filter` | Exit 1 with clear error if `target.kind == "splunk"`. |
| `ddr expire-check` | No change — target-agnostic. |
| `ddr refresh-hash` | No change in v0.3 (Sigma-only). v0.4 adds Splunk query hash refresh. |

**Examples:**
- New `examples/06-splunk-native-savedsearch/` — noisy native Splunk detection with an SPL FP filter targeting known service accounts. Files: `savedsearch.conf`, `ddr.yml`, `splunk-fragment.spl`, `README.md`.
- Examples 01–05 unchanged.

**Spec & schema files:**
- `spec/ddr-v0.3.schema.json` — regenerated from Pydantic
- `spec/ddr-v0.1.schema.json` — kept for back-compat reference
- `spec/CHANGELOG.md` — entry: additive schema change
- `spec/ddr-v0.3.md` — prose update covering native targets and the cross-field validator

### 4. Edge Cases & Error Handling

| Case | Handling |
|---|---|
| `target.kind = "splunk"` + `decision.tuning.kind = "sigma"` | Cross-field validator: "tuning shape must match target kind" |
| `splunk_filter` empty/whitespace | Pydantic field validator rejects |
| `splunk_filter` already wraps `NOT (...)` | Normalize on export — strip outer `NOT (`/`)` then re-wrap. Reuse v0.2's `_strip_not` regex. |
| `splunk_filter` contains backticks (Splunk macro) | Pass through unchanged — author's responsibility |
| `ddr new --target splunk` without `--name` and no .conf path | Error: "specify --name <stanza> or pass a savedsearches.conf path" |
| `ddr export-splunk` on Splunk target with `--config` | Warn and ignore (config has no effect on native targets) |
| `ddr export-sigma-filter` on Splunk target | Exit 1 with clear error |
| Loading a v0.1 record under v0.3 (no `target.kind` field) | Pydantic fills `kind = "sigma"` from Literal default |
| Mixed Sigma+Splunk directory in `ddr validate` | Both validate independently |
| Splunk target with `decision.kind = "deprecate"` or `"accept-risk"` | Allowed — those decisions don't carry tuning |
| Splunk savedsearch query content drifts after the DDR is written | `query_hash` is optional in v0.3; v0.4 adds `ddr refresh-hash --target splunk` |

### 6. Sigma Compatibility & Ecosystem Fit

DDR's "Sigma is source of truth" principle is **unchanged for Sigma-targeted records**. Splunk-native targets are an explicit, documented escape hatch for cases where:
- The detection lives in the SIEM only and was never authored in Sigma
- Sigma can't express the detection logic (complex aggregations, subsearches, deferred lookups)
- An org is migrating between SIEMs and wants a paper trail of FP decisions to forward-port

The upstream Sigma pitch is **strengthened**, not weakened: DDR is positioned as a *governance layer that prefers Sigma but accommodates SIEM-native reality* — a more honest sell to detection teams who don't have 100% Sigma coverage.

Field vocabulary: native-target tuning bypasses the Corelight/Zeek field map. Author writes SPL in their own field vocabulary. The spec calls this out — native records are inherently non-portable, and that's the whole reason for the escape hatch.

### 7. Final Plan Summary

v0.3 lifts DDR's Sigma-only target assumption with an additive schema change: a discriminated union over `target.kind` (`sigma` | `splunk`) and a parallel discriminated union over `decision.tuning` shape, tied together with a cross-field validator. New `SplunkTarget` references a savedsearch by name + app; new `SplunkTuning` carries a raw SPL filter clause. `ddr new` gains `--target` (minimal scaffold for Splunk; full .conf parsing in v0.4); `ddr export-splunk` branches on target kind so Splunk-native records work without sigma-to-spl installed; `ddr export-sigma-filter` errors clearly on native targets. One new worked example, full back-compat for v0.1/0.2 records, regenerated `spec/ddr-v0.3.schema.json`, and ~15 new tests. No behavior changes for Sigma-targeted records.

## Architecture notes

**Discriminated-union pattern (Pydantic v2):**
```python
Target = Annotated[SigmaTarget | SplunkTarget, Field(discriminator="kind")]
Tuning = Annotated[SigmaTuning | SplunkTuning, Field(discriminator="kind")]
```
Pydantic resolves on the literal `kind` field. v0.1 records without `kind` default to `"sigma"` because that's the Literal default on `SigmaTarget.kind`.

**Cross-field validator (`DDRRecord`, mode="after"):**
```python
if isinstance(self.decision, SuppressDecision):
    if self.target.kind != self.decision.tuning.kind:
        raise ValueError(
            f"tuning.kind '{self.decision.tuning.kind}' must match target.kind '{self.target.kind}'"
        )
```

**Splunk filter normalization:** reuse v0.2's `_strip_not` regex. Strip leading `NOT (`/trailing `)` so the author can write either `NOT (host=foo)` or just `host=foo` and the export wraps consistently.

**No sigma-to-spl required for Splunk targets** — the export branch returns immediately after normalization, never imports `sigma_to_spl`. CI proves this by running the new example's export step in a job *without* sigma-to-spl installed.
