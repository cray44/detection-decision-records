# DDR v0.2 — Splunk Export Design

**Status:** Plan approved. Awaiting IMPLEMENT signal.  
**Decided:** 2026-05-06  
**Scope:** `ddr export-splunk` command — SPL NOT clause from a suppress DDR's tuning block, lowered via sigma-to-spl.

---

## Decision

Option A: Splunk export from a Sigma-targeted DDR. sigma-to-spl does the lowering.  
NOT Option B (Splunk-native target) — that's v0.3+.

---

## 7-Section Plan (locked)

### 1. Goal & Success Criteria

`ddr export-splunk <path>` takes a suppress DDR and emits a SPL NOT clause ready to append to an existing Splunk detection search. sigma-to-spl's `SplunkBackend` + `PostProcessor._apply_field_map()` do the lowering so field names are Corelight/Zeek-correct.

**Success:** given any existing suppress example, `ddr export-splunk ddr.yml` outputs SPL that a Splunk engineer can paste directly as a `NOT (...)` clause. Field names match what sigma-to-spl produces from the same rule.

### 2. Proposed Changes

**New:** `src/ddr/exporters/splunk.py`
- `build_splunk_suppression(record, config) → str` — the SPL NOT clause
- `export_to_spl(record, output, format, config) → str` — CLI entry point

**CLI:** `ddr export-splunk`, parallel to `export-sigma-filter`.
- `--format fragment` (default) — bare `NOT (...)` clause
- `--format savedsearches` — `savedsearches.conf` stanza
- `--config <path>` — sigma-to-spl config YAML; defaults to `../sigma-to-spl/config/corelight.yml` if it exists

**Optional dependency:** sigma-to-spl. `try: import sigma_to_spl` with clear `RuntimeError` if missing. Not added to `pyproject.toml` (not on PyPI).

**No schema changes.** v0.1 tuning block is already correct shape.

**Examples:** all three suppress examples get a `splunk-fragment.spl` generated file.

### 3. Impact

- Schema: zero changes
- CLI: one new command
- Examples: three new `splunk-fragment.spl` files
- CI: new step re-running `ddr export-splunk` on each suppress example

### 4. Edge Cases

| Case | Handling |
|------|----------|
| sigma-to-spl not installed | `RuntimeError` with install instructions |
| condition isn't simple `not <name>` | Strip outer `not`/`not (...)`, warn on complex boolean; still attempt |
| SplunkBackend can't translate a modifier | Surface as `ConversionError` with offending field |
| decision.kind != suppress | Exit 1 (same as export-sigma-filter) |
| No corelight.yml found | Fall back to `SplunkConfig()` defaults, emit warning |

### 5. Testing Strategy

- Unit: `build_splunk_suppression` with known selection → assert correct SPL NOT clause
- Unit: `--format savedsearches` → assert stanza structure
- Unit: missing sigma-to-spl import → assert `RuntimeError` message
- Integration: run against all three suppress examples, assert `NOT` present + correct field names
- Negative: non-suppress DDR → exit 1; missing sigma-to-spl → exit 1 with message

### 6. Sigma Compatibility

Lowering path: `tuning.selections` → synthetic Sigma detection block → `SplunkBackend.convert()` → `PostProcessor._apply_field_map()`. Same field translation pipeline as sigma-to-spl's rule converter. No new field vocabulary.

### 7. Final Plan Summary

Construct a minimal synthetic Sigma rule YAML from `tuning.logsource` + `tuning.selections`. Parse with `SigmaCollection`. Convert via `SplunkBackend.convert()`. Apply `PostProcessor._apply_field_map()` for Corelight field names. Strip `not` from the tuning condition to isolate the FP clause. Wrap as `NOT (...)`. Default output: bare fragment. `--format savedsearches`: conf stanza. Three suppress examples gain `splunk-fragment.spl`. CI gains export step.

## sigma-to-spl API notes (from reading source)

```python
from sigma.collection import SigmaCollection
from sigma.backends.splunk import SplunkBackend
from sigma_to_spl.postprocess import PostProcessor
from sigma_to_spl.config import default_config, load_config

# Convert a synthetic rule dict → SPL
collection = SigmaCollection.load_ruleset([tmp_rule_path])
backend = SplunkBackend()
queries = backend.convert(collection)   # → list[str], raw SPL conditions
spl = queries[0]

# Apply field map only (skip headers/index injection for a suppression fragment)
config = default_config()               # loads ../sigma-to-spl/config/corelight.yml
pp = PostProcessor(config)
spl = pp._apply_field_map(spl)
```

`default_config()` resolves to `sigma-to-spl/config/corelight.yml` via `Path(__file__).parent.parent / "config" / "corelight.yml"` — works when sigma-to-spl is installed as a sibling editable install.

`format_savedsearches(title, spl)` already exists in `postprocess.py` — reuse it.

## Condition stripping logic

DDR tuning conditions follow Sigma filter semantics. For the SPL output, we want the FP clause itself:

| DDR condition | Synthetic rule condition | SPL output wrapper |
|---|---|---|
| `not known_fp` | `known_fp` | `NOT (<spl>)` |
| `not (known_fp_1 or known_fp_2)` | `known_fp_1 or known_fp_2` | `NOT (<spl>)` |
| `known_fp` (no not) | `known_fp` | `(<spl>)` (no NOT — unusual, warn) |

Strip regex: `^not\s+\(?(.+?)\)?$` (case-insensitive).
