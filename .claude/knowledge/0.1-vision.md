# DDR v0.1 Vision (permanent context)

Goal: Ship a minimal, production-ready governance layer that detection engineers actually want to use.

Key deliverables:
- Official DDR JSON Schema (strict + extensible)
- Python CLI with four core commands
- 5+ real-world SigmaHQ worked examples
- Clear path to upstream into Sigma project

Non-goals for v0.1: full UI, database backend, advanced analytics.

Success = engineers can tune noisy rules in <5 minutes and export clean filters.

---

# DDR v1.0 North Star (permanent context)

v1.0 is DDR as a stable, multi-SIEM governance spec the Sigma community can adopt: a frozen v1 JSON Schema (target unions for Sigma + Splunk + Elastic + KQL, multi-rule targeting, cross-field validators), full export coverage (`ddr export-{sigma-filter,splunk,elastic,kql}` all SIEM-native or Sigma-lowered), 10+ worked examples spanning all decision kinds and target types, a `ddr list` summary command and automated `refresh-hash` for every target type, an upstream RFC merged or in active discussion with SigmaHQ positioning DDR as the canonical FP-tuning record format, and CI/pre-commit integrations that detection teams can drop into existing detection-as-code pipelines without modification — i.e., the "5-minute tune a noisy rule" promise from the v0.1 vision, generalized across the SIEM landscape and ratified by the ecosystem.
